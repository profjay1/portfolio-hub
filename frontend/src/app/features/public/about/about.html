About

Engineer first, generalist by habit.

I am a software engineer who enjoys the whole path a feature takes: understanding the problem, shaping the data, building the API and the interface, and making sure it runs well in production.

How I work

I prefer small, well-tested changes over big rewrites. Each piece of work starts with a short plan, ships as a focused pull request, and leaves the codebase a little clearer than before. Decisions with real trade-offs get written down as architecture decision records, so the reasoning outlives the conversation.

What I care about

  • Correctness. Tests that describe behaviour, validated inputs, and errors that tell you what went wrong.
  • Clarity. Code organised around the domain, with names that make comments mostly unnecessary.
  • Operability. Health checks, structured logs, and deploys that can be rolled back in minutes.
  • Accessibility. Interfaces that work with a keyboard, a screen reader, and a slow connection.

Outside of work

I keep learning by building things like this site, reading about distributed systems, and writing up what I learn so I can explain it clearly to others.
